# 이미지 표본 검토와 모델 추천

확인일: 2026-10-30

## 확인 범위와 선택 방법

원본 train/val ZIP에서 이미지를 읽고 6개 contact sheet를 만들어 실제로 확인했다. 각 split에서 무작위 8장, watch/tie/belt/glasses/glove/leg warmer/cape/umbrella를 각각 포함하는 8장, 라벨 수 상위 80개에서 무작위 8장을 골랐다. random seed는 4091이다. 표본은 총 48개 패널이며, 무작위 그룹 외에는 의도적으로 어려운/희귀 사례를 선택했으므로 전체 데이터의 비율을 대표하지 않는다. 작은 대상은 원본 이미지 2장도 추가로 열어 확인했다.

검토 이미지와 패널별 파일명·라벨·원본 크기 목록은 `tmp/image_review/` 아래 JPG와 JSON에 있다. 여러 사람이 있다는 과제 조건을 고려해야 하지만, 이번 표본은 주 피사체 한 명이 크게 나오는 경우가 주로 관찰됐다. 배경 인물도 있으며 이 관찰로 전체 데이터의 인원 분포를 추정하지 않았다.

## 직접 관찰한 특징

1. train 무작위 표본의 1번과 6번에는 사람이 없는 옷걸이 의류 사진이 있다. 사람 검출을 반드시 거치는 시스템이면 이런 입력을 놓칠 수 있다.
2. 런웨이, 일상 거리, 행사, 실내 제품 사진 등 배경과 촬영 조건이 다르다. 사람 전신·상반신·부분 신체 구도가 섞여 있다.
3. train 희귀/액세서리 표본 2번은 자켓 아래 넥타이가 일부만 보이고 안경도 작다. val 해당 그룹 1번은 드레스/신발에 비해 시계가 매우 작다. 둘 다 원본으로 확인했다.
4. 다중 라벨 표본에는 코트/자켓 안쪽 상의, 벨트, 스카프, 가방, 양말 등 크기가 다른 대상이 함께 있다. 가림과 겹침이 관찰된다.
5. 전신 사진의 모자와 신발은 위아래 가장자리에 위치할 수 있다. 강한 crop은 이미지 라벨은 그대로 두면서 대상을 제거할 수 있다.
6. 일부 사진은 시각적으로 보이는 물체와 제공 클래스 라벨의 대응이 추가 검토를 필요로 한다. 시각적 추정만으로 라벨 오류를 단정하거나 공식 라벨을 수정하지 않았다.

## 추천

시간상 여러 backbone 비교가 어렵고 학교 GPU 서버가 있다는 조건에서는 ImageNet-22k 사전학습 가중치의 **ConvNeXt-Small을 고정하고, 이미지 전체를 보존하는 384x384 입력으로 미세조정**하는 구성을 권한다. 처음에는 종횡비를 유지해 resize하고 padding하는 방식을 시작점으로 삼으며, padding의 비효율이나 왜곡 없는 resize 전략도 실제 검증 결과로 판단해야 한다.

이 판단은 이미지 전체 분류, 의류 형태·질감과 작은 액세서리의 동시 인식, 구현 시간, 파라미터 제한을 함께 고려한 것이다. 이미지 표본만으로 ConvNeXt가 Swin보다 우수하다는 결론을 내릴 수는 없다. 384가 224보다 좋다는 것 또한 아직 측정하지 않은 가설이다.

- 모델 ID: `convnext_small.fb_in22k_ft_in1k`
- 출력: 27 logits, BCEWithLogitsLoss로 학습 후 sigmoid와 검증에서 정한 임계값 적용.
- 분류기를 1000개에서 27개로 교체하면 약 49.48M 파라미터로 예상된다. 실제 모델 객체 전체를 계수하고 50M 이하를 검사해야 한다.
- 입력: 먼저 소량 384x384 smoke test로 GPU 메모리·처리량 확인. 처음부터 전체 이미지를 224로만 학습하는 것을 기본값으로 고정하지 않는다.
- 전처리: 전체 화면 보존을 우선하고 강한 RandomResizedCrop이나 사람 검출 기반 잘라내기를 기본 흐름으로 사용하지 않는다.
- 서버 자원: 더 큰 모델 대신 고해상도 학습과 안정적인 fine-tuning에 우선 사용한다. GPU 사양과 시간 예산에 따라 batch와 epoch를 정한다.
- 제한: 모델 미학습, 성능 미측정. 작은 액세서리의 누락 위험을 확인한 것이며 실제 오류율을 측정한 것이 아니다.
