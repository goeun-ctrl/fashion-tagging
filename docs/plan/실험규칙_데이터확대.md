# 실험 규칙: 데이터 확대 라운드 (BCE + 증류 기반)

MAT4091 Fashion Category Tagging · 팀 공유용 · 2026-11-07 · 작성: 5번

이 라운드에서 하는 실험(모자이크 강화, COCO 군중 사진 + 의사 라벨, 마스크 지도 학습)은 모두 이 규칙을 따른다. 다른 팀원이 같은 코드로 seed나 변형을 추가할 때도 같다. **규칙을 어긴 결과는 발표와 최종 선택에 쓰지 않는다.**

---

## 0. 왜 이 라운드를 하는가 (요약)

- 제공 테스트 데이터는 Fashionpedia와 다르다. 300장 중 50%가 군중 사진이고, 이미지당 정답 라벨은 약 9개다(train은 약 3개).
- 사람을 잘라 크게 보여 주면 재현율이 0.54에서 0.77로 오른다. 모델은 옷을 알아보지만, 군중 속 사람이 작아서 놓친다(스케일 문제).
- 하지만 추론 때 crop이나 타일을 일괄 적용하면 한 사람 사진(val)에서 오탐이 폭증한다(val micro 0.87 → 0.58~0.76). 그래서 **추론으로 우회하지 않고, 학습 데이터로 해결한다.**
- 지난 라운드에서 gate, 빈 사진, 옛날 사진 증강 등을 한꺼번에 합친 "최종 조합"은 val과 예시 양쪽에서 더 나빴다(val micro 0.883 → 0.861). 그래서 이번에는 **가장 좋았던 단순한 기준에 한 가지씩만 더한다.**
- 손실은 4번의 비교 결과에 따라 **BCE**를 쓴다. 고해상도 C1에서 반전 TTA와 holdout 임계값 기준으로 val micro +0.011 [+0.005, +0.017], macro는 차이가 없었다(`feature/role4-c1-bce-asl-results`).

## 1. 절대 규칙

### 1-1. 테스트 데이터

- `test_public`(300장)과 `examples_labeled`(30장)는 **평가와 진단에만** 쓴다.
- 다음은 전부 금지다.
  - 학습에 넣기, 직접 라벨링하기
  - 의사 라벨이나 증류 점수 만들기
  - 임계값, epoch, 모델, 하이퍼파라미터 고르기
  - 테스트 사진으로 증강 만들기 (모자이크 조각, 배경 등)
- 예시 30장 점수는 "경향 확인"에만 쓴다. 30장은 95% 구간이 ±0.04 정도라, 예시 점수로 둘 중 하나를 고르지 않는다.

### 1-2. 선택과 보고

- best epoch과 임계값은 **holdout(2,425장)으로만** 고른다. 공식 val(1,158장)은 보고에만 쓴다.
- val을 본 뒤에 설정을 바꾸고 싶으면 **새 실험 ID로 다시 돌린다.** 같은 ID에서 val을 보고 임계값을 바꾸지 않는다.
- 임계값은 각 모델마다 holdout에서 다시 고른다. BCE는 최적 임계값이 0.25 근처로 ASL(0.55~0.65)과 크게 다르므로, 이전 0.60 규칙을 옮겨 쓰지 않는다.

### 1-3. 데이터

- Fashionpedia: 고정 분할 `train_inner` 43,197 / `holdout` 2,425 / 공식 val 1,158을 그대로 쓴다.
- 원본 마스크(`instances_attributes_train2020.json`)는 `train_inner`에만 쓴다. holdout 마스크는 만들지 않는다.
- 외부 데이터는 COCO train2017과 Places365만 쓴다. Fashionpedia val2020 이미지는 공식 val이므로 어떤 형태로도 학습에 쓰지 않는다.
- 외부 사진의 holdout 목록(`crowd_holdout.txt`, `pos_holdout.txt`, `neg_holdout.txt`)은 학습에 넣지 않는다.

### 1-4. 모델 크기

- **50M은 제출 모델 기준이다.** 지금 기준 모델은 27.85M이다.
- 사람 검출기(Faster R-CNN 43.7M)와 의사 라벨 교사는 학습 전에 라벨을 만들 때만 쓴다. 제출 추론에는 들어가지 않는다.

### 1-5. 비교

- 비교는 **같은 seed, 같은 코드 버전**끼리만 한다. 기본 seed는 42다.
- 한 실험에서는 기준 대비 **한 가지만** 바꾼다. 두 가지를 함께 바꾼 실험은 두 요소의 상호작용을 보는 용도로만 쓴다.
- 차이는 쌍 부트스트랩 2,000회 95% 구간으로 판단한다. 구간이 0을 포함하면 "차이 없음"으로 보고한다.
- seed만 바꿔도 macro는 최대 0.02, micro는 0.001~0.003 흔들린다(최종 조합 s42 대 s43에서 잰 값). macro 차이 0.02 이하는 seed 하나로 결론 내지 않는다.

## 2. 기준 설정 (모든 실험 공통)

```bash
COMMON="--model convnext_tiny.fb_in22k_ft_in1k_384 --head linear_ms \
  --loss bce \
  --distill_npz /data/eunjin/DL/fashionformer/train_scores/ff_r50_train.npz --distill_alpha 0.5 --distill_shift 0.3 \
  --short_min 400 --short_max 800 --test_short 800 --max_long 1333 --flip 0.5 \
  --epochs 18 --batch_size 8 --accum 4 --lr_backbone 1e-4 --lr_head 1e-3 --weight_decay 0.05 --clip 1 \
  --warmup_iters 1000 --ema 0.9995 --drop_path 0.1 --seed 42 --out_dir /data/eunjin/DL/runs_hr"
```

- 나머지는 `scripts/train_hires.py` 기본값을 그대로 둔다 (lr 2/3, 11/12 지점 ×0.1, EMA 가중치로 best epoch 선택).
- gate, 빈 사진, 사람 사진, 옛날 사진, 흑백, zoom-out은 **이번 라운드에서 끈다.** 효과를 깨끗하게 보기 위해서다. 빈 사진 처리(테스트의 6%)는 이긴 설정에 나중에 다시 붙인다.
- 1회 학습 시간: A5000 한 장 기준 약 9~10시간.

## 3. 실험 목록

| ID | 헤드 | 더하는 것 | 목적 | 담당 / GPU |
|---|---|---|---|---|
| **R5_bce_kd_s42** | GAP·GMP | (없음) | **기준. 아래 실험의 비교 대상** | 미정 (팀원 서버 권장) |
| R5_bce_kd_mos9_s42 | GAP·GMP | 모자이크 강화 | 가짜 군중 사진 (Fashionpedia만) | 5번 GPU 0 |
| R5_bce_kd_pl_s42 | GAP·GMP | COCO 군중 + 의사 라벨 | 진짜 군중 사진 | 5번 GPU 1 |
| R5_bce_kd_mos9_pl_s42 | GAP·GMP | 둘 다 | 상호작용 | 5번 GPU 2 |
| R5_bce_kd_csra_mask_s42 | CSRA | 마스크 지도 학습 | 상의끼리의 혼동 (남은 오탐의 절반) | 5번 GPU 3 |

**기준 실험(R5_bce_kd_s42)이 없으면 나머지 4개의 효과를 분리할 수 없다.** 5번 GPU는 4장이 모두 차므로, 팀원 서버에서 같은 명령으로 돌려 주기를 부탁한다. CSRA 기준(BCE + 증류 + CSRA, 마스크 없음)도 있으면 좋지만 우선순위는 낮다.

### 실험별 추가 인자

```bash
# 기준
python scripts/train_hires.py --exp_id R5_bce_kd_s42 $COMMON --pool gapgmp

# 모자이크 강화: 50% 확률로 2/4/6/9장을 이어 붙임 (9 = 3x3, 라벨은 합집합 -> 이미지당 약 9개로 테스트와 비슷)
python scripts/train_hires.py --exp_id R5_bce_kd_mos9_s42 $COMMON --pool gapgmp \
  --mosaic_p 0.5 --mosaic_sizes 2 4 6 9

# COCO 군중 + 의사 라벨: epoch마다 외부 사진이 20% (매 epoch 새로 뽑음)
python scripts/train_hires.py --exp_id R5_bce_kd_pl_s42 $COMMON --pool gapgmp \
  --ext_list /data/eunjin/DL/neg_data/crowd_train.txt --ext_labels /data/eunjin/DL/neg_data/pl_kd_msmax.npz --ext_ratio 0.2

# 둘 다
python scripts/train_hires.py --exp_id R5_bce_kd_mos9_pl_s42 $COMMON --pool gapgmp \
  --mosaic_p 0.5 --mosaic_sizes 2 4 6 9 \
  --ext_list /data/eunjin/DL/neg_data/crowd_train.txt --ext_labels /data/eunjin/DL/neg_data/pl_kd_msmax.npz --ext_ratio 0.2

# 마스크 지도 학습: CSRA 점수 지도를 칸별로 원본 마스크에 맞춤 (train_inner만)
python scripts/train_hires.py --exp_id R5_bce_kd_csra_mask_s42 $COMMON --pool csra \
  --mask_dir /data/eunjin/DL/fashionpedia_ann/masks27 --mask_weight 0.5
```

- 모자이크는 Fashionpedia 사진끼리만 만든다. 외부 사진은 모자이크에 들어가지 않는다.
- 외부 사진에는 증류 점수가 없어서, 그 사진에서는 BCE만 계산된다.
- 의사 라벨의 `-1`(모름)은 손실에서 빠진다.

## 4. COCO 군중 사진과 의사 라벨 만들기

학습 전에 한 번만 한다. 5번이 만들어 서버 `/data/eunjin/DL/neg_data/`에 둔다. 다른 서버에서 쓰려면 같은 명령으로 다시 만들거나 5번에게 파일을 받는다.

### 4-1. 사진 고르기

```bash
python scripts/build_negatives.py cococrowd --n 20000
```

- COCO train2017에서 사람 박스가 2개 이상이고, 가장 큰 사람의 키가 80픽셀 이상인 사진을 고른다.
- gate holdout 사진(`pos_holdout.txt`)은 제외한다.
- 출력
  - `crowd_train.txt` 19,000장, `crowd_holdout.txt` 1,000장
  - `crowd_boxes.json`: COCO 정답 사람 박스

### 4-2. 교사 점수 매기기

- 교사: `R5_cnxt_hr_kd_msmax_s42` (증류 + GAP·GMP, ASL). val에서 가장 좋았던 모델이다.
- 방법: 전체 사진과, 키 64픽셀 이상인 큰 사람 6명의 crop을 각각 반전 TTA로 판단하고, 클래스별 최대값을 쓴다.

```bash
for k in 0 1 2 3; do CUDA_VISIBLE_DEVICES=$k python scripts/pseudo_label.py score \
  --ckpt /data/eunjin/DL/runs_hr/R5_cnxt_hr_kd_msmax_s42/best.pt \
  --list /data/eunjin/DL/neg_data/crowd_train.txt --out /data/eunjin/DL/neg_data/pl_kd_msmax \
  --shard $k --n_shards 4 & done; wait
```

### 4-3. 기준값 정하기 (holdout으로만)

- crop을 거친 점수는 오탐이 많다(한 사람 사진에서 정밀도가 0.85에서 0.50으로 떨어짐). 그래서 **holdout에도 같은 crop 방식을 적용해서** 정밀도를 잰다.
- holdout에는 COCO 박스가 없으므로, 검출기로 사람 박스를 만든다.

```bash
sed "s#^#/data/eunjin/DL/fassion_tagging/data/train/images/#" data/splits/holdout.txt > /data/eunjin/DL/neg_data/holdout_paths.txt
python scripts/pseudo_label.py boxes --list /data/eunjin/DL/neg_data/holdout_paths.txt --boxes /data/eunjin/DL/neg_data/holdout_boxes.json
python scripts/pseudo_label.py score --ckpt /data/eunjin/DL/runs_hr/R5_cnxt_hr_kd_msmax_s42/best.pt \
  --list /data/eunjin/DL/neg_data/holdout_paths.txt --boxes /data/eunjin/DL/neg_data/holdout_boxes.json \
  --out /data/eunjin/DL/neg_data/plho_kd_msmax
python scripts/pseudo_label.py calib --preds /data/eunjin/DL/runs_hr/R5_cnxt_hr_kd_msmax_s42/tta/preds_holdout_s800_flip.npz \
  --out /data/eunjin/DL/neg_data/plho_kd_msmax
```

**기준을 미리 정해 둔다.**
- 양성(1): holdout 정밀도가 **0.90 이상**이 되는 가장 낮은 확률값
- 음성(0): holdout에서 "확실히 없음"의 정확도(NPV)가 **0.995 이상**이 되는 가장 높은 확률값
- 그 사이 확률은 -1(모름)
- 정한 값과 그 근거(calib 출력)를 실험 기록에 남긴다.

### 4-4. 라벨 쓰기

```bash
python scripts/pseudo_label.py label --out /data/eunjin/DL/neg_data/pl_kd_msmax --pos_thr <4-3의 값> --neg_thr <4-3의 값>
```

출력 로그에 사진당 양성 수와 "모름" 비율이 찍힌다. 사진당 양성이 1개 미만이거나 모름이 80% 이상이면, 학습 전에 5번과 다시 상의한다.

## 5. 평가 절차 (모든 실험 동일)

학습이 끝나면 아래 순서로 평가한다. 실험 ID 자리는 `$E`로 쓴다.

```bash
R=/data/eunjin/DL/runs_hr
# 1) 반전 TTA 예측 저장 (holdout, val)
python scripts/infer_hires.py --run_dir $R/$E --scales 800:1333
# 2) holdout으로 임계값 선택 (0.05~0.95, holdout macro 최고) -> 그 임계값의 val 값 출력
python experiments/role5_regularization/defense_stats.py pick $E
# 3) 기준 대비 차이와 클래스별 분해 (T = 2에서 고른 임계값)
python experiments/role5_regularization/defense_stats.py macro R5_bce_kd_s42:<T_base> $E:<T> --out $R/$E/vs_base.json
# 4) 테스트 분포 확인 (예시 30장 F1, 테스트 300장 예측 수) - 확인용, 선택에 쓰지 않음
python scripts/eval_ood.py --ckpt $R/$E/best.pt --out $R/$E/ood/eval --threshold <T> \
  --class_threshold "sweater=0.5" "leg warmer=0.5" "umbrella=0.5"
```

- 2번의 `pick`은 sweater, leg warmer, umbrella를 0.5로 둔다 (`--special`). 이 예외는 지난 라운드의 holdout 표에서 정한 것이라, 바꾸지 않고 모든 실험에 똑같이 적용한다.
- 4번은 예시 30장의 사진 유형별(군중, 2~4명, 1명) 재현율도 함께 본다 (`experiments/role5_regularization/error_sheet.py`).

## 6. 판정 기준 (미리 정함)

새 설정을 **채택**하려면 아래를 모두 만족해야 한다.

1. val micro와 image가 기준 실험보다 **유의하게 나쁘지 않다** (구간 하한이 −0.005보다 위).
2. val macro가 기준보다 유의하게 나쁘지 않다. 단, 양성 7장 이하 클래스 4개(cape, tie, leg warmer, umbrella)를 뺀 macro도 함께 보고한다.
3. 예시 30장의 군중 사진 재현율이 기준보다 오른다. 30장이라 판정이 아니라 **방향 확인**이다.
4. 테스트 300장에서 사진 유형별 예측 수가 테스트 분포와 맞는 쪽으로 움직인다.
   - 군중 사진: 늘어야 한다.
   - 1명 사진: 거의 그대로여야 한다.
   - 사람 없는 사진: 늘면 안 된다.

1, 2를 통과하지 못하면 3, 4가 좋아도 채택하지 않는다. 테스트 분포만 보고 고르지 않기 위해서다.

## 7. 기록과 보고

- 실행 결과는 `<out_dir>/<exp_id>/`에 남긴다 (`config.json`, `history.csv`, `summary.json`, `best.pt`, `tta/`, `ood/`).
- 실험 ID 규칙: `R<역할>_<손실>_<주요 설정>_s<seed>` (예: `R5_bce_kd_mos9_s42`). 다른 팀원은 자기 역할 번호를 쓴다.
- 보고 표 형식 (같은 표 안에서만 비교)

| ID | 임계값 (holdout 선택) | holdout micro / macro / image | val micro / macro / image | 기준 대비 val micro [95% 구간] | 예시 micro / 군중 재현율 | 테스트 이미지당 예측 (군중 / 1명 / 사람 없음) |
|---|---|---|---|---|---|---|

- 중요한 epoch만 보고한다 (best epoch, 마지막 epoch). 모든 epoch을 나열하지 않는다.
- 결과 파일과 문서는 각자 브랜치(`feature/<역할>-<내용>`)에 올리고, main 병합은 팀에서 정한다.
