## 1. 과제 조건 (변경 없음, 허용 사항 추가)

- 27개 클래스 멀티라벨이고 지표는 Micro / Macro / Image-wise F1이다. 지표 가중치는 아직 공지되지 않았다.
- 최종 추론에 쓰는 **모든 모델 파라미터의 합이 50,000,000개 이하**여야 한다. 검출기를 쓰면 검출기 전체가 포함된다.
- 모델과 임계값은 train/val로만 고른다. 공개·비공개 테스트로 학습하거나 튜닝하면 안 된다. 오프라인으로 실행해야 한다.
- **추가 허용 (11-06)**: Fashionpedia로 학습된 공개 체크포인트를 초기값이나 구성 요소로 쓸 수 있다.
  - **[확인 필요]** 아래 두 가지는 별도 질문이다 (8장).
    - Fashionpedia 원본 박스·마스크·속성 주석을 학습에 직접 쓰는 것
    - 학습에만 쓰는 보조 헤드가 50M에 포함되는지
- **누출 주의**: 공개 체크포인트는 Fashionpedia `train2020`으로 학습한 것이어야 우리 val이 깨끗하다. val까지 넣고 학습한 체크포인트는 val 점수가 부풀려지니 쓰지 않는다. 비공개 테스트가 Fashionpedia test(논문 기준 2,044장)라면, train만 학습한 체크포인트는 문제없다. **[확인 필요]** 체크포인트마다 학습 split을 확인해서 기록한다.

## 2. 지금까지 실측 결과

### 2-1. 백본 기준선 (공식 val)
| 실행 | 데이터 | val micro | val macro | val image |
|---|---|---|---|---|
| ConvNeXt-T 384 (2번) | 원본 | 0.826 | **0.661** | 0.828 |
| EVA02-S 378 (3번) | 원본 | 0.811 | 0.632 | 0.816 |
| EVA02-S 378 기본 (5번 재실행) | 공통 506 | 0.812 | 0.625 | 0.811 |
| **EVA02-S 378 + wd 제외 + drop path + EMA** (5번) | 공통 506 | **0.840** | **0.659** | **0.841** |

- **EMA 조합만 유의했다.** 기준선 대비 val micro +0.028 [+0.020, +0.037], image +0.030 [+0.020, +0.040] (쌍 부트스트랩 95% 구간). macro +0.034는 구간이 0에 걸친다. 자세한 내용은 `experiments/role5_regularization/results_eva02.md`에 있다.
- **wd 제외와 drop path 단독은 기준선과 구분되지 않았다.**
- **ConvNeXt 1차 (5번, holdout)**: Muon은 lr 배율 ×4가 가장 좋았고, drop path 0.1이 1위였다. LP-FT와 layer decay 0.8은 손해였다. 자세한 내용은 `experiments/role5_results_convnext.md`에 있다.

### 2-2. 공통 데이터 패키지 1단계
- 외부 이미지는 뽑기의 1.9%, 색 변화는 13.5%에만 적용됐다. 반전은 기존에도 있었다. 결국 모델이 보는 데이터가 기존과 거의 같다.
- 외부 이미지에는 분위기 차이가 있다. 원본은 패션 사진인데 외부는 COCO/OpenImages 일상 장면이다. 음성 라벨은 47개뿐이고, jumpsuit가 작업복인 것처럼 클래스 뜻이 맞지 않는 경우가 있다. leg warmer 크롭은 epoch마다 장당 약 2.2번 반복된다.
- 결론: 외부 데이터로 점수를 올리기는 어렵다. 구할 수 있는 외부 데이터도 이게 전부다.

### 2-3. 오류 진단 (EVA02 EMA 조합, val) **[실측]**
| 유형 | 클래스 | 근거 |
|---|---|---|
| **작은 물체** | watch(train 3,373장, F1 0.42), sock 0.46, scarf 0.52, belt(6,667장, 0.61) | 데이터가 많아도 낮다. 재현율이 0.33~0.57이다 |
| **비슷한 의류 혼동** | jumpsuit → pants+top, cardigan → top·shirt, cape → jacket·coat, vest → top | 놓친 경우 대신 예측한 클래스 |
| **표본 부족** | leg warmer(61장), cape(152), umbrella(134) | val에 5~7장뿐이라 측정도 불안정하다 |

- **입력이 정보를 잃는다.** 원본은 83%가 세로 사진이고 긴 변 중앙값이 1024px이다. 378 정사각형에 넣으면 0.37배로 줄고, 실제 사진은 캔버스의 67%만 차지한다.
- **모델이 희귀 클래스에 "없다"고 하는 쪽으로 치우쳐 있다.** 정밀도는 높고 재현율은 낮다. 클래스별 최적 임계값은 27개 중 21~24개가 0.5보다 낮았다.
- **사후 임계값 조정은 효과가 작다.** holdout으로 클래스별 임계값을 맞추고 val에 적용하면 macro는 +0.005~0.008, micro는 −0.005~0.009다. 희귀 클래스 표본이 적어 임계값이 과적합된다.
- **과적합이 빠르다.** 모든 실행에서 2~3 epoch 이후 holdout BCE가 오른다. train BCE는 0.004까지 내려간다.
- **두 백본이 같은 천장에 있다.** 그래서 병목은 백본이 아니라 공통 입력·헤드·손실 쪽으로 본다.

## 3. 전략: 세 트랙

### 트랙 A: 분류기 개선 (기존 백본, 비용 작음) · 우선
진단된 원인을 하나씩 직접 고친다. EMA는 모든 실행의 기본으로 깐다.
1. **해상도와 입력 형태**: EVA 378 → 518, ConvNeXt 384 → 512. 정사각형 패딩 대신 세로 비율(예: 384×576)도 비교한다. 노리는 것은 작은 물체 재현율이다.
2. **쿼리 헤드**: C2(`--head query`), C3(`--head query_ms`, stride 16+32). 5번 코드에 이미 구현돼 있다. 노리는 것은 작은 물체와 비슷한 의류 혼동이다.
3. **손실**: BCE vs ASL (γ−=4, γ+=0, clip 0.05). 이미 구현돼 있다. 노리는 것은 재현율이고, 가중 복원 추출 대신 쓴다.
4. **보조**: label smoothing 0.05~0.1, 실제 학습 길이(약 15 epoch)에 맞춘 cosine 일정.

### 트랙 B: Fashionpedia 체크포인트 활용 · 새로 추가
Fashionpedia는 **우리 train과 같은 이미지에 박스·마스크로 학습한** 검출·분할 모델이 공개돼 있다. 원래 해상도(약 1024px)에서 객체 단위로 보기 때문에, 작은 물체 문제에 직접 강하다.

| 후보 | 형태 | 프레임워크 | 상태 |
|---|---|---|---|
| Attribute-Mask R-CNN (Fashionpedia 원 논문) | 검출+분할+속성 | TensorFlow (tensorflow/tpu) | 체크포인트가 있다고 안내됨. **[확인 필요]** 백본, 학습 split, 파라미터 수 |
| FashionFormer (ECCV 2022) | 분할+속성 | mmdet 2.18 / PyTorch 1.9 | 체크포인트 링크 있음 (OneDrive/Baidu). 학습 데이터는 `train2020`. **[확인 필요]** 백본, 파라미터 수 |
| Facere (FashionFail, Mask R-CNN) | 검출+분할 | ONNX | Fashionpedia-train으로 fine-tuning한 것으로 공개됨. **[확인 필요]** 크기, 라이선스 |
| YOLOS-Fashionpedia (Hugging Face) | 검출 (46개 카테고리) | transformers | 바로 쓸 수 있다. **[확인 필요]** 학습 split, 정확도, 파라미터 수 |

활용 방식은 세 가지이고, 비용이 낮은 순서로 시도한다.
- **B1. 백본 초기값**: 검출기의 백본(예: ResNet-50)을 가져와 우리 분류 헤드를 붙이고 fine-tuning한다. 패션 이미지에 이미 적응한 특징으로 시작할 수 있다. 구현이 가장 쉽다.
- **B2. 검출 → 이미지 라벨**: 검출 결과를 클래스별로 최대 점수로 모아서 이미지 단위 확률로 쓴다. 단독으로 쓰거나, 분류기 확률과 평균을 낸다.
- **B3. 검출기 + 분류기 앙상블**: 파라미터 합계 50M 안에서 조합한다 (예: 작은 검출기 + EVA02-S 21.8M). 4장의 예산표를 실측해서 맞춘다.

**채택 조건**: 트랙 A의 최고 단일 모델보다 val과 holdout에서 모두 유의하게 높을 것 (6장 기준). 그리고 오프라인 추론 환경(`requirements.txt`)에서 재현될 것.

### 트랙 C: 데이터 (우선순위 낮춤)
- **외부 데이터 2단계**: 1단계 진단의 문제(분위기 차이, 음성 부족, 반복 노출)를 먼저 해결해야 의미가 있다. LVIS/OpenImages 박스로 사람이나 아이템 주변을 잘라내고, LVIS의 음성 카테고리로 0 라벨을 채우고, 반복 횟수에 상한을 두는 식이다. 트랙 A·B 이후에 여유가 있으면 진행한다.
- **Fashionpedia 원본 주석 활용**: 허용되면(8장 질문 1) 박스로 작은 아이템을 잘라낸 학습 이미지를 만들거나, 보조 위치 손실을 붙인다. 허용 전에는 진행하지 않는다.

## 4. 실험 로드맵

한 실험에서 하나만 바꾼다. 모든 실행은 seed 42, EMA 0.9995, holdout으로 선택하고, val은 보고에만 쓴다.

| STEP | 실험 | 고정 | 다음 단계 조건 | 상태 |
|---|---|---|---|---|
| 1 | 기준선 (ConvNeXt-T, EVA02-S) | | | **완료** |
| 2 | 정규화: EMA, drop path, wd 대상 | | | **완료**: EMA 채택 |
| 3 | **해상도·입력 형태**: 378/384 vs 518/512 vs 세로 비율 | 백본별 EMA 조합 | watch·belt·sock·scarf 재현율이 오르고, val micro가 구간 밖으로 개선 | 다음 |
| 4 | **헤드**: C1 vs C2 vs C3 | STEP 3 최선 | 위와 같음, 혼동 클래스 F1 | 다음 |
| 5 | **손실**: BCE vs ASL (+ label smoothing) | STEP 3·4 최선 | 희귀 클래스 재현율 개선, micro·image 유지 | |
| 6 | **트랙 B1**: Fashionpedia 백본 초기값 | STEP 3~5 설정 | 트랙 A 최선보다 유의하게 높음 | 체크포인트 조사 중 |
| 7 | **트랙 B2/B3**: 검출 기반 예측, 앙상블 | 파라미터 실측 | 위와 같음 + 추론 시간 | |
| 8 | 임계값: 공통 최적값 (클래스별은 제한적으로) | 저장한 logits | holdout과 val 모두 개선 | |
| 9 | 최종 후보 seed 3개 재학습, 파라미터 실측 | 선택 규칙 사전 기록 | | |
| 10 | 제출 점검 (오프라인 `predict.py`, JSONL, ZIP) | | 모든 이미지에 유효한 레코드 1개 | |

STEP 3~5는 EVA와 ConvNeXt를 병렬로 돌린다. 연구실 서버의 GPU 4장으로 한 번에 4개 실행을 돌릴 수 있고, 실행 하나는 약 2.5시간이다 (해상도를 올리면 1.5~2배).

| 항목 | v1 | v2 |

## 6. 평가·선택 규칙 (구체화)

- 세 F1과 클래스별 support/TP/FP/FN/P/R을 항상 저장한다.
- **유의성**: 같은 이미지를 복원 추출하는 쌍 부트스트랩(2,000회)으로 기준 대비 차이의 95% 구간을 계산한다. 구간이 0을 포함하면 "차이 없음"이다. 스크립트는 `experiments/role5_regularization/bootstrap_eval.py`이다.
  - 참고 크기 [실측]: val 단일 실행의 95% 구간은 micro ±0.012, macro **±0.04**다. val macro 0.01 차이로는 판단하지 않는다.
- **seed**: 채택 후보는 seed 3개의 평균과 범위로 확정한다.
- **판단 순서**: holdout과 val에서 방향이 같을 때만 채택한다. val은 반복해서 볼수록 낙관적이 되니, 튜닝은 holdout으로 한다.
- **희귀 클래스**(val 양성 10장 미만: tie, cape, umbrella, leg warmer)는 holdout과 val을 합친 수치로 따로 보고한다.

## 8. 남은 조교 질문

## 10. 위험 요소

- **검출기 프레임워크**: TF(tpu)나 mmdet 2.x(PyTorch 1.9)는 우리 환경(PyTorch 2.x)과 맞지 않는다. 변환이 필요하면 비용이 커진다. 오프라인 `predict.py`에 넣을 수 있는지 먼저 확인한다.
- **파라미터 합계**: 검출기를 쓰면 50M 여유가 거의 없다. 앙상블 조합이 제한된다.
- **추론 시간**: 1024px 검출은 느리다. "5,000장을 현실적인 시간 안에" 처리할 수 있는지 STEP 7에서 측정한다.
- **val 누출**: 체크포인트의 학습 split을 확인하지 않으면 val 점수를 믿을 수 없다 (1장).
- **해상도 증가 비용**: 학습 시간이 1.5~2배다. GPU 4장 기준으로 STEP 3~5를 하루 안에 끝내려면 실행 수를 제한해야 한다.

## 11. 보류·폐기

| 항목 | 결정 | 이유 |
|---|---|---|
| 외부 데이터 대량 투입 | 보류 | 1단계 진단 결과, 분위기와 라벨 문제를 먼저 해결해야 한다 |
| 클래스별 임계값 전면 적용 | 폐기 (제한적 사용만) | [실측] val macro +0.005~0.008, micro는 손해 |
| LP-FT, layer decay (ConvNeXt) | 보류 | [실측] 1차에서 손해. EVA에서는 lr을 올린 layer decay만 STEP 5 이후 검토 |
| Muon (ConvNeXt) | 옵티마이저 비교 트랙으로 분리 | 이번 백본 개선 범위가 아니다 |
| 스크래치 학습 | 폐기 | 4.3만 장으로는 사전학습 모델보다 크게 불리하다 |
